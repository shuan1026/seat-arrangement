## 1. 產品定位

Seat Arrangement 是尾牙承辦人在活動前安排座位的工具，只服務一場尾牙。

- 系統維護兩份名單：**員工名單**是公司全部員工；**參與人員**是報名尾牙的員工、他們的眷屬與外部貴賓。兩份分開匯入與維護，員工名單上看得到誰還沒報名。
- 承辦人把參與人員用拖移安排到場上的桌，隨時看得到誰還沒入座、哪一桌還有位子；桌子可以在 30 個固定位置之間搬動、暫放到暫存區、新增或刪除（D-027）；活動當天值勤的工作人員放在工作人員桌。
- 活動當天用它查某人坐哪一桌，並看入座統計。
- 座位表匯出成和座位圖同樣版面的 Excel 檔，交給餐廳與現場工作人員。
- 座位排好後發布座位表，同仁用公司帳號登入發布頁，查自己坐哪一桌（`permissions.md`）。
- 只有編輯者可以修改資料；檢視者可以看排座資料、不能修改；其他同仁登入後只能看發布的座位表（第 2 節）。

介面的三個做法：

- **一個畫面做完：** 座位安排頁左邊是人員、右邊是座位圖，拖過去就入座，不用切換頁面。
- **桌次自己說明：** 每一桌除了桌號，還顯示組成這一桌的部門，以及手動加上的備註名稱。
- **改了就存：** 每一次拖移、新增、編輯、刪除都立即儲存，沒有儲存鈕；重新開啟或換裝置都看到最新結果。

### 1.1 使用對象

| 對象 | 要做什麼 |
|---|---|
| 尾牙承辦人 | 匯入員工名單、把報名的員工加入尾牙、維護參與人員、安排全部座位、設定桌次備註、匯出座位表 |
| 協辦同仁 | 協助確認自己部門誰報名、安排自己部門的座位 |
| 現場工作人員 | 活動當天查某人坐哪一桌，看統計列的入座人數 |
| 全體同仁 | 座位表發布後，在發布頁查自己坐哪一桌 |

承辦人與協辦同仁要被設為編輯者才能修改資料；現場工作人員等需要查看排座資料的同仁要被設為檢視者；其他同仁登入後只能看發布的座位表（第 2 節）。

### 1.2 核心情境

階段 3 的端到端測試照這條流程走。

| 步驟 | 發生什麼 | 頁面 |
|---|---|---|
| 1 | 用公司 Google 帳號登入 | 登入 |
| 2 | 承辦人（編輯者）把協辦同仁設為編輯者、把現場工作人員設為檢視者 | 權限 |
| 3 | 承辦人匯入公司員工名單（姓名、部門、組別、分機） | 員工名單 |
| 4 | 在員工名單看誰還沒報名，把報名的員工加入尾牙，帶眷屬的一併加上；或直接匯入參與人員名單 | 員工名單、參與人員 |
| 5 | 按「自動排座」依部門與組別一次排好，再在座位圖把人員拖到桌次微調；整桌要換位置時拖桌次的把手到另一桌對調 | 座位安排 |
| 6 | 為主桌、貴賓桌設定備註名稱（主桌、董事貴賓、供應商） | 座位安排 |
| 7 | 名單異動：新增眷屬、標注兒童椅與素食、指定工作人員、取消報名的人移出 | 參與人員、座位安排 |
| 8 | 匯出座位表給餐廳與現場工作人員：Excel 檔，版面和座位圖一樣 | 參與人員 |
| 9 | 發布座位表；同仁用公司帳號登入發布頁，搜尋自己的姓名找到座位 | 座位安排、發布頁 |
| 10 | 活動當天用手機搜尋某人坐哪一桌，看統計列的入座人數 | 座位安排 |

### 1.3 這一版不做

- 員工名單和人資或通訊錄系統同步（以承辦人匯入的檔案為準）
- 列印版面、桌卡與名牌（座位表只提供 Excel 匯出）
- 報到、簽到與抽獎
- 素食以外的餐點與飲食偏好（素食只標注是或否）
- 多場活動或歷年座位表（一次只處理一場尾牙）
- 多人同時編輯的即時同步
- 資料備份與還原

## 2. 使用者與權限

- 要用公司 Google 帳號登入，只允許公司網域的帳號（第 8 節）。
- 公司帳號登入後分三種身分（D-021、D-026）：權限頁名單上的帳號依各自的權限是編輯者或檢視者；不在名單上的沒有權限，只能看發布頁。

| 身分 | 誰 | 可以做什麼 |
|---|---|---|
| 編輯者 | 權限頁名單上、權限是「編輯者」的帳號；第一位由部署時的環境變數指定（`permissions.md`） | 全部功能，包括所有會修改資料的操作：新增、編輯、刪除、加入尾牙、取消報名、匯入、入座與搬移、備註名稱、自動排座、復原、發布設定與權限設定 |
| 檢視者 | 權限頁名單上、權限是「檢視者」的帳號，由編輯者在權限頁新增 | 看座位安排、參與人員、員工名單三頁，內容和編輯者相同；搜尋、篩選、縮放、展開、找人、查看詳情與匯出座位表；不能修改任何資料。畫面上以「只能檢視」表示（COM-R20） |
| 沒有權限 | 其他公司帳號 | 只能看發布頁 `/seats`；開其他頁時顯示「沒有權限」頁（AUTH-R16） |

- 發布頁 `/seats` 發布後，三種身分都能看（`permissions.md`）。
- 每個人登入後的首頁都是座位安排；沒有權限的人在那裡看到「沒有權限」頁。
- 權限怎麼判斷、權限變更何時生效、被拒絕時怎麼處理，見第 8.3 節。

| 編號 | 規則 |
|---|---|
| COM-R19 | 檢視者看到的資料和編輯者相同，包括分機、素食、兒童椅與備註。所有會修改資料的入口都隱藏，不是停用：新增、匯入、編輯、刪除、加入尾牙、取消報名、入座與搬移的選單項目、拖移（含桌次的拖移把手）、備註名稱欄位、自動排座、「發布」與權限頁。列操作選單只留不修改資料的項目；一個項目都沒有時，不顯示列操作按鈕。搜尋、篩選、分頁、縮放、展開、找人、查看詳情、前往其他頁的按鈕與匯出座位表照常。各頁隱藏哪些操作見 `seating.md` SEAT-R90、`participants.md` PPL-R86、`employees.md` EMP-R67。 |
| COM-R20 | 檢視者的 Header 右側，原本儲存狀態的位置顯示中性徽章「只能檢視」（桌面與 Mobile Header 都有）。檢視者不會儲存任何資料，所以不顯示儲存狀態，只顯示徽章。 |

## 5. App Shell（PLT-01）

| 區域 | 做法 |
|---|---|
| Sidebar | 桌面展開 240 px、收合為 48 px 圖示列，固定在視窗內距 24 px，底色 `--sidebar`，外框 `--sidebar-border`。切換鈕在 Header；視窗低於 1024 px 時預設收合 |
| Logo 區 | 展開 208 × 72 px 放完整 Logo（符號加字標），收合 24 × 24 px 只放符號；瀏覽器分頁圖示也用符號。單色：淺色表面用 `--color-text`，深色表面用白色版；深色主題時 Sidebar、Drawer 與登入頁的 Logo 都用白色版（D-020）。檔案在 `ui-design-system/assets/logo/`：`logo-dark.svg`、`logo-light.svg`（完整 Logo）與 `symbol-dark.svg`、`symbol-light.svg`（符號），`dark`／`light` 指 Logo 本身的顏色。Logo 與配色已確認：Logo 用這組圓桌座位標誌，色彩用多彩活力 |
| 導覽項目 | 座位安排、參與人員、員工名單、權限，各配一個 Lucide 圖示（`armchair`、`users`、`id-card`、`key-round`）；「權限」只有編輯者看得到（第 4 節）。圖示用 `--muted-foreground`；目前頁面用 `--primary` 12% 的淡色底加 `Text-sm/Medium`；收合時以 Tooltip 顯示名稱 |
| 使用者區塊 | 依設計系統的 Sidebar User Footer 放在 Sidebar 底部：32 px 圓形頭像（`--sidebar-avatar-bg` 底、`--sidebar-avatar-fg` 字，放姓名的第一個字），旁邊兩行是姓名 `Text-sm/Semi Bold` 與 email `Text-xs/Regular`，最右是 `chevrons-up-down` 圖示。Sidebar 收合時只剩頭像，滑過以 Tooltip 顯示姓名。點開是 Dropdown Menu `user-menu`，在觸發區右側、底邊對齊：第一列是姓名與 email，下面只有「登出」（`log-out` 圖示）。手機放在 Drawer 底部，選單往上開、和觸發區同寬 |
| Header | 約 48 px，跟著頁面捲動，沒有底色。左側是 Sidebar 切換鈕，右側依序是介面配色鈕（COM-R17）與儲存狀態（第 6 節）；檢視者的儲存狀態位置改為中性徽章「只能檢視」（COM-R20）。桌面與手機的 Header 都不顯示產品名稱與頁面標題 |
| 內容區 | 底色 `--background`，內容放在 `--card` 面板，頁面標題（H1）在內容區最上方 |
| 手機（767 px 以下） | 不顯示桌面 Sidebar，改為固定在頂部的 Mobile Header 與 Mobile Drawer。Mobile Header 左側是選單鈕，右側依序是介面配色鈕與儲存狀態（檢視者是「只能檢視」徽章）；Logo、導覽與使用者區塊在 Drawer 裡 |

- 切換頁面時只更換右側主畫面，導覽與 Header 維持不動，資料不重新載入。
- 開啟網址進入座位安排；沒登入時先到登入頁（第 8 節）。

## 6. 立即儲存與儲存狀態（PLT-02）

| 編號 | 規則 |
|---|---|
| COM-R01 | 每一次新增、編輯、刪除、加入尾牙、取消報名、入座、搬移、移出、調整順序、清空、對調、自動排座、復原、權限頁的新增帳號、改權限與移除帳號、切換發布，都在操作完成時立即儲存，沒有儲存鈕。 |

| COM-R02 | 操作後畫面立即反映結果；儲存中 Header 顯示「儲存中…」，完成後顯示「已儲存 {時:分}」。 |
| COM-R03 | 操作依發生順序一個一個儲存，後面的操作不會比前面的先存。 |
| COM-R04 | 儲存失敗（網路或系統錯誤）時顯示「儲存失敗，請檢查網路後再試一次。」與「重試」；畫面上的結果保留；按「重試」從失敗的那一次接著存，成功後才更新時間。 |
| COM-R05 | 重新整理或換裝置開啟，看到的是最後儲存的結果。 |

## 7. 多人同時操作

| 編號 | 規則 |
|---|---|
| COM-R06 | 畫面不會自動更新別人的改動，重新整理後才看到。 |
| COM-R07 | 別人剛改過資料，使這一次操作不能完成時（例如桌次已被別人坐滿、員工已被別人加入尾牙、資料已被別人刪除），這次操作不儲存，還沒存的後續操作一併取消，畫面重新載入最新資料。 |
| COM-R08 | COM-R07 的情況：違反的規則有既有提示時用那句提示（例如桌次已滿）；其他情況以 Sonner 顯示「資料已被其他人更新，已重新載入。」 |
| COM-R09 | 不違反任何規則的操作照常儲存；兩人先後改同一筆資料（例如同一桌的備註名稱）時，以後改的為準。 |

## 8. 登入、登出與權限（PLT-04）

### 8.1 畫面

- 登入頁不套 App Shell。整頁底色 `--background`，背後兩團光暈（`--glow-primary`、`--glow-accent`），光暈只是裝飾層，不承接文字、不擋點擊、不造成水平捲動。
- 畫面中央一張寬 400 px 的卡片（`--card`、邊框 `--border`、圓角 `--radius-xl`、陰影 `--edge-highlight` 加 `--shadow-xs`），由上到下置中排列完整 Logo、標題（H1）、說明；下面是錯誤提示（有錯誤時才出現，Alert）與登入按鈕（Button `primary`，滿版，`log-in` 圖示）。
- 手機上卡片寬度隨視窗縮小，左右留 16 px。
- 「沒有權限」頁（AUTH-R16，D-026）和登入頁相同：不套 App Shell，底色、光暈與卡片的樣式都一樣，沒有介面配色鈕，配色沿用這個瀏覽器的選擇（COM-R18）。卡片由上到下置中排列完整 Logo、標題（H1）「你沒有檢視權限」、說明，以及目前登入的帳號（`Text-sm/Regular`、`--muted-foreground`；email 太長時換行，可以在任何字元處換行，不截斷）；下面是「查看座位表」（Button `primary`，滿版）與「登出」（Button `outline`，滿版），上下排列。手機同登入頁。

### 8.2 登入規則

| 編號 | 規則 |
|---|---|
| AUTH-R01 | 沒登入時開任何頁面都先到登入頁；登入後回到原本要開的頁面（含網址參數）。直接開登入頁時，登入後進入座位安排。 |
| AUTH-R02 | 只有 email 網域等於公司網域 `program.com.tw` 且 Google 已驗證 email 的帳號能登入。承辦人、協辦同仁與現場工作人員都有公司 Google 帳號，手機上也能登入（已確認）。 |
| AUTH-R03 | 其他帳號不登入，留在登入頁顯示「這個帳號不能登入。」錯誤提示。 |
| AUTH-R04 | Google 登入沒有完成（使用者取消、Google 回傳錯誤、網路問題）時，留在登入頁顯示「登入沒有完成。」錯誤提示。 |
| AUTH-R05 | 按下登入後，按鈕的圖示換成載入中，按鈕不能再按。 |
| AUTH-R06 | 登入狀態保留 30 天，持續使用會自動延長。 |
| AUTH-R07 | 登入過期後的下一次操作不儲存，畫面回到登入頁並顯示「登入已過期。」提示；登入後載入最新資料。 |
| AUTH-R08 | 沒登入時呼叫任何 API 都被拒絕（健康檢查除外），不回傳任何資料。 |
| AUTH-R09 | 登出：按 Sidebar 底部的使用者區塊，選「登出」，不需確認；回到登入頁並以 Sonner 顯示「已登出。」登出後按上一頁也看不到資料。 |
| AUTH-R10 | 使用者區塊與選單顯示登入者的 Google 帳號姓名與 email；頭像放姓名的第一個字。 |

### 8.3 權限

| 編號 | 規則 |
|---|---|
| AUTH-R11 | 登入者的 email 在權限名單上（`permissions.md`，比對方式見 PRM-R03）時，依名單上的權限是編輯者或檢視者；不在名單上就沒有權限（D-021、D-026）。每一次開啟頁面與每一次操作都依當下的名單判斷，權限變更從對方的下一次開啟頁面或操作起生效，對方不必重新登入或登出。 |
| AUTH-R12 | 檢視者呼叫任何會修改資料的 API 都被拒絕，資料不變。讀取資料的 API 與匯出座位表只接受編輯者與檢視者；發布頁用的 API 只要登入就能用（AUTH-R15）。 |
| AUTH-R13 | 畫面開著時被改為檢視者的編輯者，下一次修改資料的操作被拒絕：這次操作不儲存，還沒存的後續操作一併取消，開著的對話框關閉，畫面重新載入最新資料並切換成只能檢視（COM-R19、COM-R20），以 Sonner 顯示「你沒有編輯權限，已重新載入。」。當時在權限頁的人回到座位安排。被移除權限的編輯者見 AUTH-R17。 |
| AUTH-R14 | 畫面開著時被設為編輯者或檢視者的人，畫面不會自動改變（COM-R06）；下一次開啟或重新整理頁面時依新的權限顯示，不必重新登入：檢視者看到三頁的內容，編輯者另有編輯操作與「權限」導覽。開著「沒有權限」頁的人被加入後，重新整理同一頁就看得到內容。 |
| AUTH-R15 | 發布頁 `/seats` 也要登入：沒登入時依 AUTH-R01 先到登入頁，登入後回到 `/seats`。編輯者、檢視者與沒有權限的公司帳號都能看（`permissions.md`）。 |
| AUTH-R16 | 沒有權限的人開座位安排、參與人員、員工名單或權限頁時（含直接開網址，以及登入後進入的座位安排），網址不變，在那一頁顯示「沒有權限」頁（第 8.1 節），不載入任何排座資料；讀取資料的 API 與匯出座位表都被拒絕，不回傳資料（D-026）。按「查看座位表」前往 `/seats`；按「登出」依 AUTH-R09 登出（不需確認，回到登入頁並以 Sonner 顯示「已登出。」）。 |
| AUTH-R17 | 畫面開著時被移除權限的人，畫面不會自動改變（COM-R06）。檢視者在下一次開啟或重新整理頁面、或按「匯出座位表」時看到「沒有權限」頁，匯出不下載檔案。編輯者的下一次修改資料的操作被拒絕：這次操作不儲存，還沒存的後續操作一併取消，開著的對話框關閉，畫面換成「沒有權限」頁，不顯示 Sonner（D-026）。 |

## 11. 設計規範

視覺一律以 `ui-design-system/` 為準。這是活動前密集使用的工作工具，走安靜的商業 SaaS 介面：中性表面，色彩只留給主要動作與狀態。

- 實作 UI 前依 `AGENTS.md` 的 UI Design System 一節讀設計系統：頁面區塊照原型 HTML，元件照 `03-components.md`，顏色、字級、間距、圓角、陰影一律用語意 token，不寫死色碼。
- 座位安排、參與人員、員工名單、權限頁、發布頁、對話框不加頁面光暈；空狀態只在圖示後方用 `--glow-empty`；登入頁用 `--glow-primary` 與 `--glow-accent`。
- 配色有淺色（多彩活力）與深色兩種，切換與記住的方式見 COM-R17、COM-R18（D-020）。

### 11.1 色彩

每個顏色都有固定用途：藍色是動作與可放置的目標，琥珀是搜尋標示，綠、琥珀、紅表示狀態。琥珀、綠在白底上對比不足，只當填色與邊框，當文字時用對應的深色 token。

| 用途 | 語意 token | 用在 |
|---|---|---|
| 頁面與卡片 | `--background`、`--card`、`--sidebar`、`--popover` | 內容區、座位圖底、桌次、面板、表格、對話框、側選單、下拉選單；卡片靠 `--border` 與 `--edge-highlight` 分層 |
| 表面 | `--muted` | 地標（舞台、出入口）、Tabs 底、中性徽章、禁用態、空位列 |
| 主色 | `--primary` | 主要按鈕、選取、目前導覽、可放置的桌次邊框；文字 `--primary-foreground` |
| 強調 | `--accent` | 搜尋命中的桌次邊框 |
| 正向 | `--status-positive-bg`／`--status-positive-fg` | 已滿、已報名徽章 |
| 待處理 | `--status-pending-bg`／`--status-pending-fg` | 未入座、未報名、超過徽章 |
| 危險 | `--destructive`、`--destructive-text` | 刪除、取消報名、清空桌次、欄位錯誤 |
| 主要文字 | `--foreground` | 標題與內文 |
| 次要文字 | `--muted-foreground` | 說明、座號、分機、空桌 |

狀態徽章的形狀與尺寸依 Badge（`rounded=true`），一律包含文字：

| 語意 | 背景／文字 token | 圖示 | 狀態 |
|---|---|---|---|
| 正向 | `--status-positive-bg`／`--status-positive-fg` | `check` | 已滿、已報名、已發布（D-021） |
| 待處理 | `--status-pending-bg`／`--status-pending-fg` | `clock` | 未入座、未報名 |
| 待處理 | `--status-pending-bg`／`--status-pending-fg` | `triangle-alert` | 超過（桌次 11、12 位，D-018） |
| 中性 | `--muted`／`--muted-foreground` | 無 | 空桌、工作人員、不參加（D-014）、未發布、只能檢視（D-021） |

不代表狀態的標示：類別「貴賓」用 Badge `outline`；「兒童椅」與「素食」用 `third` 的 16 px 小徽章，分別只放 `baby` 與 `leaf` 圖示、滑過顯示 Tooltip；桌次「{桌號}」用 `outline`（可按下，在座位圖標示那一桌）。眷屬已經寫在顯示名稱裡（「_眷屬」），不另加徽章。徽章內的圖示暫定 12 px，放在文字前，間距 `--space-1`。

### 11.2 字級

字型使用 `--font-sans`，字級使用 `text-styles.json` 的 token，不另外指定大小與字重。

| 層級 | Token | 用在 |
|---|---|---|
| 頁面標題 | `Text-2xl/Bold` | 每頁的 H1 |
| 區塊標題 | `Text-lg/Semi Bold` | 面板與 Dialog 標題 |
| 桌號 | `Text-xl/Semi Bold` | 座位圖上的桌號、桌次詳情標題 |
| 內文 | `Text-sm/Regular` | 內文、表格、表單 |
| 強調 | `Text-sm/Medium` | 按鈕、Tabs、人員列的顯示名稱、備註名稱 |
| 輔助文字 | `Text-xs/Regular` | 桌次名單、部門、分機、統計列 |

| 介面 | 設計系統元件 | 注意事項 |
|---|---|---|

| 次要動作 | Button `outline` | 取消、匯入員工名單、匯入參與人員、匯出座位表、全部展開、自動排座、發布、複製連結 |

| 圖示 | Lucide outline | 線條粗細用 `--stroke-width` |

## 12. 文案規範

- **語氣**：操作導向、短句、明確動詞，避免行銷口吻與過度解釋介面。
- **稱呼**：介面用「你」。
- **按鈕**：動詞開頭，說清楚按下去會發生什麼，例如「清空桌次」，不寫「確定」。
- **錯誤訊息**：先說發生什麼，再說下一步。不顯示錯誤代碼，不責怪使用者。
- **排版**：使用全形標點；中文與英文、數字之間加半形空格。人數比例用半形「8/10」。
- **變數**：`{}` 內為系統帶入的內容。
- **桌號**：`{桌號}` 是桌次的桌號 A1～A15、B1～B15（D-019）。單獨出現時寫「A1」（座位圖的圓桌、參與人員頁的桌次欄、桌次徽章）；標題與句子中寫「A1 桌」，例如「已把 {顯示名稱} 安排到 {桌號} 桌。」。同一句有兩桌時，另一桌寫成 `{原桌號}`（搬移前的桌）或 `{目標桌號}`（對調的另一桌），見 `seating.md`。
