| 項目 | 內容 |

## 1. 範圍

| 編號 | 功能 | 說明 |
|---|---|---|
| PRM-01 | 權限管理 | 權限頁列出所有有權限的帳號與各自的權限（編輯者或檢視者），新增（只接受公司網域）、改權限與移除；第一位編輯者由環境變數指定（D-021、D-026） |
| PRM-02 | 座位發布 | 座位安排頁的「發布」對話框開啟或停止發布、複製連結；發布頁 `/seats` 讓所有公司同仁登入後查自己的座位 |

- 本檔包含：權限頁、權限名單的規則、發布對話框、發布頁。
- 不在本檔：三種身分（編輯者、檢視者、沒有權限）的定義與檢視者的共同做法（`README.md` 第 2 節）；權限的判斷、權限變更何時生效、寫入被拒時的處理、「沒有權限」頁、發布頁要登入（`README.md` 第 8 節）；座位安排、參與人員、員工名單在只能檢視時隱藏哪些操作（`seating.md` SEAT-R90、`participants.md` PPL-R86、`employees.md` EMP-R67）；座位圖的排列、桌次的樣子與縮放（`seating.md`）。

## 3. 規則

### 3.1 權限名單

| 編號 | 規則 |
|---|---|
| PRM-R01 | 權限名單上的帳號依各自的權限是編輯者或檢視者；不在名單上的公司帳號登入後沒有權限，只能看發布頁（`README.md` 第 2 節、AUTH-R11、AUTH-R16，D-021、D-026）。名單存 email 與權限，每個 email 只有一種權限；不必是員工名單上的人，也不必登入過。 |
| PRM-R02 | 第一位編輯者由部署時的環境變數 `INITIAL_EDITOR_EMAILS`（以逗號分隔的 email）指定。伺服器啟動時，權限名單是空的，就把這些 email 以編輯者寫進名單；寫入後和在權限頁新增的編輯者完全相同，可以改權限或移除。名單不是空的時不讀這個變數，改變數不會增減名單上的任何帳號。變數裡不是公司網域或格式不對的 email 略過。名單是空的、變數也沒有設定時，沒有人能修改資料，也沒有人能看座位安排、參與人員、員工名單三頁，要設定變數後重新部署。沒有設定變數時，啟動流程不讀寫權限名單（不碰資料庫）。檢視者沒有對應的環境變數，一律在權限頁新增（D-026）。 |
| PRM-R03 | email 一律去掉前後空白、英文字母轉成小寫後再比對與儲存。登入者的 email 也照這個方式和名單比對，所以「A@Program.com.tw」和「a@program.com.tw」是同一個人。 |
| PRM-R04 | 名單至少要有一位編輯者，最後一位編輯者不能移除，也不能改為檢視者（PRM-R12）。 |
| PRM-R05 | 新增、改權限與移除都從對方的下一次開啟頁面或操作起生效，對方不必重新登入（AUTH-R11、AUTH-R13、AUTH-R14、AUTH-R17）。 |

### 3.2 權限頁

| 編號 | 規則 |
|---|---|
| PRM-R06 | 導覽的「權限」只有編輯者看得到。檢視者直接開 `/permissions` 時導向座位安排（`/`），不顯示提示；沒有權限的人開 `/permissions` 時，和開其他頁一樣顯示「沒有權限」頁（AUTH-R16）。讀取或修改權限名單的 API 只接受編輯者。 |
| PRM-R07 | 清單列出名單上全部帳號的 email 與權限，依加入的先後排列，最早加入的在最上面；改權限不改變位置。 |
| PRM-R08 | 新增：在「email」欄位輸入、在「權限」選單選擇（預設「檢視者」），按「新增」或在 email 欄位內按 Enter。下列情況不新增，錯誤顯示在 email 欄位下方：空白「請輸入 email。」；不是 email 格式「請輸入正確的 email。」；網域不是公司網域 `program.com.tw`「只能新增公司帳號（@program.com.tw）。」；已經在名單上（依 PRM-R03 比對，不論選的是哪一種權限）「{email} 已經是{權限}。」，{權限} 是這個帳號目前的權限「編輯者」或「檢視者」；要改權限用清單那一列的權限選單。 |
| PRM-R09 | 新增成功：這個 email（依 PRM-R03 轉成小寫）以選的權限加到清單最後，email 欄位清空，權限選單回到「檢視者」，Sonner 顯示「已把 {email} 設為{權限}。」，不帶「復原」；要撤銷就改權限或移除。 |
| PRM-R10 | 按下時這個 email 剛被別人加入名單：不新增，欄位顯示「{email} 已經是{權限}。」（別人加入時的權限），畫面依 COM-R07 重新載入最新的名單。 |
| PRM-R11 | 移除：按那一列的「移除」，編輯者與檢視者都以 Alert Dialog 確認。按「移除權限」：從名單移除，這個帳號之後沒有權限（AUTH-R16），Sonner 顯示「已移除 {email} 的權限。」，不帶「復原」；要恢復就重新新增。按「取消」不改變。 |
| PRM-R12 | 名單只剩一位編輯者時，那一列的權限選單與「移除」停用，清單下方顯示「至少要有一位編輯者，最後一位不能移除，也不能改為檢視者。」；檢視者那幾列照常可以改與移除。伺服器也檢查：送出移除或改為檢視者時名單只剩這一位編輯者（例如另一位編輯者剛移除自己或剛把自己改為檢視者），不儲存，依 COM-R07、COM-R08 重新載入並顯示「資料已被其他人更新，已重新載入。」。 |
| PRM-R13 | 移除自己（開得了權限頁的一定是編輯者）：確認的內文改為提醒「這是你自己的帳號。移除後你看不到排座資料，只能看發布的座位表，也不能再開啟這一頁。」。確認後畫面換成「沒有權限」頁（AUTH-R16），不顯示 Sonner。 |
| PRM-R14 | 要改權限或移除的帳號剛被別人移除：不儲存，依 COM-R07、COM-R08 重新載入並顯示「資料已被其他人更新，已重新載入。」。 |
| PRM-R15 | 新增、改權限與移除都立即儲存（改為檢視者與移除在確認後），依 `README.md` 第 6 節更新儲存狀態。 |
| PRM-R35 | 改權限：在那一列的權限選單選另一種權限。檢視者改為編輯者：立即儲存，不需確認，Sonner 顯示「已把 {email} 改為編輯者。」。編輯者改為檢視者：以 Alert Dialog 確認，按「改為檢視者」才儲存，Sonner 顯示「已把 {email} 改為檢視者。」；按「取消」不改變，選單仍顯示「編輯者」。Sonner 都不帶「復原」，要改回就再改一次。兩位編輯者先後改同一個帳號的權限時，以後改的為準（COM-R09）。 |
| PRM-R36 | 把自己改為檢視者：確認的內文改為提醒「這是你自己的帳號。改了之後你只能檢視，不能再修改資料，也不能再開啟這一頁。」。確認後回到座位安排，Sonner 顯示「已把 {email} 改為檢視者。」，畫面切換成只能檢視（COM-R19、COM-R20）。 |

### 3.3 發布

| 編號 | 規則 |
|---|---|
| PRM-R16 | 「發布」只有編輯者看得到（SEAT-R90）。按下開啟「發布座位表」對話框。 |
| PRM-R17 | 預設是未發布。對話框顯示目前狀態：已發布時勾選框打勾、徽章「已發布」；未發布時勾選框不打勾、徽章「未發布」。 |
| PRM-R18 | 「連結」欄位顯示發布頁的完整網址，也就是目前網站的網址加上 `/seats`；未發布時也顯示。欄位是唯讀的，可以手動選取。按「複製連結」把網址複製到剪貼簿，Sonner 顯示「已複製連結。」（複製失敗時見 PRM-Q02）。 |
| PRM-R19 | 切換發布開關立即儲存，不需確認：打勾時 Sonner「已發布座位表。」，取消時「已停止發布座位表。」，徽章跟著改變。Sonner 不帶「復原」，要改回就再切換一次。兩位編輯者先後切換時，以後切換的為準（COM-R09）。 |
| PRM-R20 | 發布不會鎖住任何資料：發布後編輯者照常修改，發布頁顯示最新的座位（PRM-R29）。 |

### 3.4 發布頁

| 編號 | 規則 |
|---|---|
| PRM-R21 | 發布頁的網址固定是 `/seats`，要用公司 Google 帳號登入（AUTH-R15）；編輯者、檢視者與沒有權限的公司帳號看到的內容相同（D-026）。 |

| PRM-R22 | 未發布時，頁面只有 H1 與「座位表還沒有發布，請稍後再看。」，編輯者也一樣；伺服器不回傳任何座位資料。 |
